01 / The testbed

Build the interaction.
Then bring it into the room.

Testing several speech agents normally means arranging speakers, microphones and a physical space. MuDuSi brings those early experiments into a shared virtual room, reducing the hardware setup needed to explore how agents listen, respond and speak over one another.

See multi-agent interaction
Watch independent speech models in 3D, with speaking and receiving activity, overlap, microphone levels and timing on one screen.
Change what agents hear
Move participants, vary microphone noise, add divider attenuation and compare quiet, interruption and cocktail-party scenes.
Inspect trajectories for RL research
Replay acoustic rollouts alongside audio, state, activity timelines and reward diagnostics; retain the evidence needed to develop model-side learning interfaces.
Run independent experiments
Use separate processes, ports, worker allocations and output folders for multiple sessions. Each viewer observes one experiment.

Simulation supports early testing and controlled comparisons. Physical microphones, loudspeakers and room measurements remain important for deployment validation.

02 / Conversations

Listen to a shared world.

Each agent generates its own speech. The simulator carries that sound through the room into the other agents’ microphones, letting conversations unfold without assigned speaking turns.

These are selected excerpts from actual model runs. Video audio mixes the agents’ emissions; speech bubbles replay offline ASR at word timestamps. Each agent’s spatially mixed receiver audio is saved separately. The clips illustrate interaction, not a conversation-quality benchmark.

03 / Simulation

One room. Different microphones.

The agents do not exchange text messages. They emit audio into a shared space, and each hears its own local mixture of the others. Moving an agent changes distance, attenuation and arrival time. Dividers, microphone noise and a simple wall reflection change what reaches each listener.

The 3D viewer shows speech activity, received levels, overlap and timing. Recorded input and output WAVs, acoustic state and buffer diagnostics make the interaction inspectable after the GPU run ends. Different configurations can be compared through separate recorded sessions.

The current acoustic model is deliberately lightweight: distance loss, divider attenuation, propagation delay, one wall reflection and independent microphone noise. It is not a measured room impulse response or a binaural renderer.

Speaker diarization and audio-scene understanding depend on the connected model and any added task-specific adapters or evaluation code. The simulator supplies acoustic conditions and known source identities; its activity indicators are not inferred speaker labels or evidence of scene understanding.

04 / Two workflows

Observe a conversation.
Keep the interaction.

A

Inference & evaluation

Connect speech-model workers, set the room and run a bounded conversation. Inspect who spoke, what each agent heard, and whether audio arrived on time. Replay the resulting experiment in the browser without holding a GPU.

Evaluation instructions ↗
B

Acoustic trajectory collection

Use the same evaluator to retain synchronized source, receiver and model-input audio, per-frame state, acoustic rewards and transport diagnostics. These recordings support analysis and the development of future learning interfaces.

Full speech-model RL is not implemented. Native inference traces do not yet include action tokens, behavior log-probabilities or policy-version barriers. A separate CPU example trains a small speak/listen gate with REINFORCE.

05 / Get started

Run an experiment.

Install the simulator and connect your model workers using the repository’s setup guide. PersonaPlex and Moshi need separate Python environments because both use the moshi package name.

Record a conversation with running model workers
mudusi evaluate \
  --models configs/local-workers.json \
  --seconds 60 --output runs/conversation
Replay the finished recording on CPU
mudusi serve \
  --replay runs/conversation --port 18766

Open http://localhost:18766/?showcase for the presentation view. Word-timed speech bubbles require the optional offline ASR step. On the shared GPU cluster, launch model inference through the supplied Slurm scripts.
